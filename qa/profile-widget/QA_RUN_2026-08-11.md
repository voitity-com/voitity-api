# Profile widget QA run - 2026-08-11

## Scope

- API ownership, public configuration, enable/disable lifecycle, logging, cache behavior and interaction attribution.
- Admin settings tabs, instructions, code copy, restrictions and preview.
- External launcher isolation, desktop panel, mobile full-screen chat and keyboard close behavior.
- Real public chat request through the embedded profile.

## Local fixture

- Admin: `http://localhost:3000/dashboard/profiles/2/settings?tab=widget`
- Public profile: `http://localhost:3001/abel-dev`
- Host fixture: `qa/profile-widget/fixture/index.html`
- Viewports: desktop and `390 x 844` mobile.

Do not copy the public key recorded during a run into reusable test data. Obtain the current key from the admin screen as described in `README.md`.

## Functional and visual results

1. The default Settings tab remained Features and retained the existing Products and Integrations switches.
2. The Widget tab loaded its persisted state, unique code, instructions and restrictions.
3. Copy code produced the loader URL, public widget key and API URL without exposing an authenticated token.
4. Disabling the widget made the public endpoint unavailable and removed the launcher on the next host-page load. Re-enabling restored it.
5. The public response returned `Cache-Control: no-store, private`, so toggles are not hidden behind a shared HTTP cache.
6. The host fixture applies intentionally aggressive global CSS to buttons, images and iframes. The circular Bigmelo launcher remained visually isolated through Shadow DOM.
7. Desktop opened a fixed chat panel and mobile opened a full-screen chat at `390 x 844` without horizontal loss.
8. The launcher disappeared while the panel was open, the close control worked, and Escape closed the desktop panel and restored focus to the launcher.
9. The preview modal remained inside the viewport, rendered the real loader on a dark simulated host page, opened the actual bottom-right chat panel, and could be closed with its explicit X control.
10. A real embedded text prompt requesting the exact phrase `Widget funcionando.` received `Widget funcionando.` from profile `abel-dev`.
11. The embedded profile used the `widget_chat` analytics surface.
12. An administrator could manage a profile owned by another user without leaving the publication-status error previously shown on the settings screen.

## Issues found and corrected during the run

- The HTML `hidden` attribute was overridden by the launcher's `display:flex`; a specific hidden rule now removes it while chat is open.
- The preview iframe initially exceeded shorter desktop viewports; its height is now viewport-bounded and the dialog has an explicit close button.
- A 60-second public cache could delay disablement; the public configuration now uses `no-store`.
- The base profile endpoint denied administrators even though the profile-specific admin endpoints allowed them; administrator read access and its regression test were added.
- The disable help text now accurately says that an already installed widget disappears on the next host-page load.

## Restrictions not simulated

- Browser microphone permission was not granted during this run. The microphone control and iframe permission declaration were verified, but a real audio capture still requires explicit browser/user permission and HTTPS outside localhost.
- Production CSP and third-party CMS sanitizers were documented and represented by the hostile-CSS fixture, but each customer's CSP or site builder must be tested in its own environment.
